## Included in this release

### GDAgent

- Conversation resume now follows you when you switch conversations inside an agent (for example `/clear` in Claude Code or `/new` in Codex): the tab reopens the conversation you last saw, not the one it launched with
- Dragging files from your file manager onto a terminal now pastes their paths instead of importing them into the project, like any terminal emulator; drops anywhere else still import as usual
- If a resume attempt fails right away and a fresh conversation is started, your previous conversation is set aside instead of forgotten, and it is picked up again on a later launch if the fresh one never got going

### Godot MCP

- Runtime tools now target a single game session instead of broadcasting to every instance, so `runtime.eval` no longer runs in each running instance and no longer returns a previous call's result. With several instances running (Debug > Customize Run Instances), pass `session_id` to choose one; otherwise the lowest ready session is used
- `runtime.run` now resets readiness, so `poll_until_ready` waits for the relaunched game instead of reporting the previous session
- `node.connect` now saves signal connections into the scene and warns when the target method does not exist
- Scripts are reloaded from disk before use, so exports and methods added to a file on disk are visible right away; newly written scripts register with the editor immediately so their `class_name` is known
- `script.validate` and `runtime.eval` now compile-check in a fresh script and report the compiler's own messages, reading the file from disk rather than the editor's cached copy
- Added `index` to `node.create` and `node.reparent`, and a new `node.move` action to reorder a node among its siblings
- Node-typed exports set through `node.update` are now saved as real node references instead of plain paths
- Input map actions now edit the project's own input settings (previously only editor actions were visible), and are saved to `project.godot`
- `get_errors` now returns one entry per debugger error with the correct severity and details; warnings are one-line strings, and warnings from the `runtime.eval` harness no longer clutter the Debugger panel
- Control anchor warnings now only appear under non-Control 2D parents; under a Node3D or plain Node, anchors resolve against the viewport
- Improved `help` output for the `editor` and `project` tools
- `editor.get_warnings` now filters by exact path
- Fixed the runtime summaries returned by `runtime` actions
