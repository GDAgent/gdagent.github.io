## Included in this release

### GDAgent

- Added support for Godot 4.8; one build runs on Godot 4.6 and newer
- GDAgent no longer turns off the editor's Restore Scripts on Load setting, so open scripts come back when you reopen a project. If the setting was stuck off, it is switched back on once
- Editor settings GDAgent changes while running now return to your values even after a crash
- Terminals no longer inherit the session of a Claude Code that launched Godot, which turned off transcript saving in new tabs

### Godot MCP

- Fixed an editor crash when a tool call arrived while the editor was busy saving, importing or registering classes; calls now wait until it is done
- Mouse positions now reach the game (they arrived as 0,0), clicks without a position stay where the mouse is, and `runtime.click` lands correctly in stretched games. New `space` option accepts `window`, `viewport` or `world` coordinates
- Screenshots can be cropped and enlarged for pixel art (`region`, `around_node`, `zoom`), and `batch` screenshots now update the saved file and return its path
- `runtime.eval` allows longer scripts by default, reports when `max_frames` cut it short, and names the limit and script line on a timeout. Warnings from eval code no longer appear in `get_errors`
- Held inputs (`frames_held`, `h.tap`) survive the game window losing focus, and inputs that don't register are reported
- `node.create` with `instance_scene` no longer writes the instance's values into the parent scene as overrides
- `node.update` keeps a String export as a String even if it holds a `res://` path, and reports a resource that was rejected
- Scenes are no longer saved while one of their scripts has errors, which wrote `= null` over its exports
- Node results name the scene they used, and `script.set_script` and `script.detach` accept `target_scene`
- `script.validate` waits for a new `class_name` to register instead of asking you to try again
- New `editor.eval` runs a GDScript snippet inside the editor and returns its values and `print()` output, with `await` support; runtime errors are reported immediately with the line number. `editor.run_script` now returns the script's output as well
- When the game stops in the debugger on a runtime error or breakpoint, runtime requests now fail right away with the error and stack instead of timing out. Code the agent ran (`eval`, `batch`, `call`) is resumed automatically and the reply waits until the game runs again; pass `resume_on_error: false` to keep it paused
- `runtime.unpause` now checks that the game keeps running and reports when it stops again right away (for example an error that repeats every frame)
- `runtime.get_errors` and `runtime.get_output` work while the game is paused, and repeated errors and warnings are collapsed into one entry with a count
- New `runtime.perf` measures frame time (median, p95, spikes), CPU/GPU render time and engine monitors; also available as `h.perf()` in `runtime.eval` and as a `batch` step
- `runtime.run` accepts `wait_ready: true`, so launching and waiting for the game is one call
- Screenshots can be saved to any path at full resolution, with or without returning the image (`save_path`, `include_image`)
- `runtime.eval` keeps multi-line strings exactly as written, no longer fills the Debugger panel with style warnings from eval code, and gains `h.render_frames()`; results from an abandoned eval can no longer be returned to a later call
- Renaming or moving files and folders moves `.uid`/`.import` files along and updates references in scenes, resources, scripts and project settings; `project.delete` accepts several paths, removes side files and lists remaining references; new `project.scan`. `project.write` creates missing folders
- `resource.get` shows typed arrays and built-in sub-resources correctly and can read the file on disk instead of the editor's copy (`from_disk`); new `resource.reload` refreshes the editor's copy after outside edits
